# Rehearsal 网关第三层：阶段 3 设计

状态：2026-10-20 实施设计。入口是 `SandboxRunner` 驱动的任务；`GatewaySession.decide()` 仍是唯一裁决点。

## 边界与触发

只有现有策略给出 `ALLOW` 或已有精确批准的 `CONFIRM` 后才考虑彩排。`fs.read` 等只读调用直接返回。`exec.run` 在绊网命中出口、敏感路径、提权、数据搬运信号或删除命令时触发；`net.fetch`、`git.push`、`mcp.call`、`memory.write` 属于外部副作用候选。现有 `BLOCK` 和 `CONFIRM` 的优先级不变，用户的精确批准也不能覆盖新的硬性 `BLOCK`。

开关 `AGENT_GUARD_REHEARSAL_ENABLED` 控制第三层，默认关闭；阶段 1 原始精确归因门槛尚未达到，先作为可选实验能力。没有 `SandboxRunner` 上下文的直接 API 调用没有可重放的任务起点，记录为不可用，沿用判定层结果。

## 执行流程

1. 主任务开始时保存只读工作区快照。真实 Agent 仍在现有 `network=none`、只读根文件系统、非特权容器中运行。
2. 高风险调用到达 `decide()` 时，收集调用自身的绊网信号。只使用已记录的低信任工具结果定位工作区文件；能定位时，在快照副本中将含风险命令或目标的行替换为**等字符数**的中性内容，其余行和文件不改。
3. 在另一个同等隔离的容器中从任务起点重跑净化副本。`fs.read`、`fs.write`、`exec.run` 只作用于副本；网络、推送、MCP、记忆和子代理调用只记候选，不执行副作用。彩排运行使用独立审计库，不向主任务注入工具结果。
4. 比较原始候选的行为信号与净化轨迹。原始 `exec.run` 的绊网信号若在完整净化轨迹中消失，或外部动作的同类目标在净化轨迹中消失，产生 `attributed_risk` 事实；否则为 `not_attributed`。净化未完成、找不到可净化来源或设施故障时为 `unavailable`。
5. 将 `RehearsalFacts` 回填 `EvalContext`，再次执行原策略。默认策略只对 `status=attributed` 增加 `BLOCK`；`unavailable` 回退原有判定。净化文件数、影子轨迹工具摘要、事实和耗时按同一 `call_id` 写入主审计链。

这是任务级反事实重跑：判据是**高危行为是否消失**，不使用调用序列是否完全一致。阶段 1/2 的良性采样已显示序列本身噪声很高。已有语义研判先于彩排运行，提供“规则 + LLM”中的语义层；重跑由同一 LLM 驱动，最终 `BLOCK` 仍由策略规则决定。

## 安全与降级

净化重跑永不执行网关侧外部副作用；容器与主任务具有相同的网络、挂载和特权限制。彩排的临时工作区、容器和审计库在结束时清理。若快照、Docker、LLM 或净化定位失败，记录 `unavailable` 并沿用原裁决；原沙箱硬边界保持有效。重复的相同候选及相同来源可复用事实，审计标记 `cached`。任务内已读取的来源证据会保留，以便后续重试仍可定位初始快照中的文件。

局限：净化来源定位依赖已读文件与工具结果的内容对应；动态生成内容、远程页面和不在工作区的来源无法安全改写，结果为 `unavailable`。完整重跑可能改变模型采样；默认策略因此只阻断“原始运行有具体高危信号、净化运行完整且信号消失”的情况。现有阶段 2 的 20/20 是已显现攻击的绊网召回，不等同于所有投毒任务的命中率；阶段 3 的上线报告须同时列出这两个分母。

## 验收

- Docker e2e：流程注入触发高危命令、净化副本无该行为，真实命令在 `decide()` 被拒；直接由用户要求的同类动作在两边保留；外部副作用在净化副本未执行。
- 关闭开关或注入彩排设施故障后，原判定结果不变；审计事件标明 `unavailable`。
- 报告触发量、可归因量、不可用量、误报、净化重跑墙钟耗时 p50/p95；阶段 2 的单次运行中位约 9–10 秒，先以 p95 ≤ 30 秒为实验预算，超出则保持关闭开关并优化。
