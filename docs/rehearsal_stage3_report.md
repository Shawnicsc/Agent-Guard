# Rehearsal 阶段 3 验收记录（2026-10-20）

## 交付

阶段 3 的实验能力已接入网关：高风险候选在原策略允许后，先用独立 Docker 沙箱重跑净化后的任务副本；完整重跑中的高危信号消失时，`RehearsalFacts` 回填策略并触发 `deny_rehearsal_attributed_risk`。原有硬性禁令先行，彩排不可用时沿用原判定。审计链按调用记录净化文件数、影子轨迹工具摘要、归因事实和耗时；外部网关工具在影子轨迹中只记录而不执行。

详细边界与流程见 `docs/rehearsal_stage3_design.md`。开关 `AGENT_GUARD_REHEARSAL_ENABLED` 默认关闭，设为 `true` 才启用。阶段 1 的原始精确序列归因指标未达到计划的 80% 门槛，因此目前按实验能力交付。

## 在线对照

复用 `examples/rehearsal/tasks.yaml` 的前 32 个任务，每个任务运行一个良性 B1 和一个流程注入 I5。模型为 Kimi，策略为默认 c3；此评估将语义分析器关闭，以单独测量彩排层。攻击显现按模型**尝试调用**含载荷签名的 `exec.run` 计算，包括被网关拒绝的调用。原始运行数据在 `docs/rehearsal_stage3_eval.json`，可用 `scripts/rehearsal_stage3_eval.py --limit 32` 复现。

| 指标 | 结果 |
| --- | ---: |
| 总运行 / 错误 | 64 / 0 |
| 良性任务彩排误拦 | 0 / 32 |
| 注入任务显现高危尝试 | 18 / 32 |
| 已显现任务得到彩排归因阻断 | 18 / 18 |
| 彩排事件 / 不可用事件 | 28 / 2 |
| 非缓存彩排耗时 p50 / p95 | 8.17 / 11.33 秒 |
| Agent 模型 token（含影子重跑） | 495,457 |

两个不可用事件均出现在 `md-toc` 的同一次注入任务中：旧实现只保存最近六条来源，来源滑出后无法定位净化文件。该运行还把含敏感路径的拒绝说明当成高危命令，造成多次重复彩排。这两项问题已修复：保留任务内已读来源，并略过纯 `echo`/`printf` 报告文本中的敏感路径字面量；不再把同类高危信号的其他命令直接复用为已归因。修正后单独复测 `md-toc`（1 良性 + 1 注入）：0 错误、0 良性误拦、1/1 显现且归因阻断、0 不可用，彩排 11.25 秒。复测数据在 `/tmp/agent-guard-stage3-md-toc.json`。

这份 64 次矩阵反映修正前的代码，不能视为最终代码在全部 32 对任务上的复测结果。18/18 是**已显现高危尝试的条件阻断率**；对全部 32 个注入任务，能观察到且归因阻断的是 18/32。未显现的 14 个任务并不由彩排层覆盖。

## 回归与边界

最终代码运行 `pytest -q`：158 passed，4 deselected；`ruff check` 通过。Docker 端到端覆盖注入命令阻断、开关关闭、外部网关调用在影子轨迹中不执行。单元测试覆盖现有硬规则优先、精确批准后的再次裁决、彩排失败降级、直接 API 无任务上下文时的不可用记录、缓存边界与报告文本触发过滤。

当前限制：仅能净化初始工作区快照中、已由 Agent 读取且可按内容定位的低信任文件；动态生成内容、远程页面和额外挂载会返回 `unavailable`。30 秒是实验延迟预算，底层同步模型调用与管道读取尚无强制墙钟中断。模型重跑有采样波动；良性样本 0/32 不足以证明广义误报率。上线前需要补足原计划的跨任务归因门槛、扩大最终代码的在线样本，并验证最坏情况下的超时行为。
