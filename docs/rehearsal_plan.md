# 沙箱彩排（Rehearsal）三阶段执行计划

日期：2026-10-19。目标：把沙箱从"被动损失上限"升级为"主动动态研判层"——先彩排、看行为、归因、再决定真跑。三阶段串行，每阶段有验收门槛，不达标即停。

## 背景与思路

现有防线是判定层（规则 + 污点 + 语义，调用前静态研判），bankfull 实验已证明它把 ChatInject 攻击从 8.6% 压到 0%（[bankfull_banking_report.md](bankfull_banking_report.md)）。本计划验证下一层：**沙箱内彩排**

1. 沙箱隔离性天然把恶意行为变成无害可观测的事件（`network=none` 让外传失败、敏感路径不存在、提权被拒）——把这些失败升级为检测信号（绊网）；
2. 同一任务"原始内容 vs 净化内容"各跑一遍，轨迹分歧定位恶意动作——反事实因果归因，判定行为是用户意图还是注入导致；
3. 都成立后作为网关第三层产品化：高危动作触发彩排，裁决结果回填策略引擎。

## 阶段 1：bankfull 数据验证归因逻辑（零成本，半天）

**目标**：验证"轨迹分歧点定位恶意动作"的归因精度，不写新防线代码。

**做法**：新增 `scripts/attribute_bankfull.py`，对 bankfull direct/monitor 数据：

1. 配对：每条攻击运行 ↔ 同 arm 同用户任务的无攻击基线，提取两侧工具调用序列（`requested_tool_calls`）；
2. 求分歧点：序列对齐，找首个分歧位置（工具名或参数不同）；
3. 判定分歧性质：分歧点动作是否命中注入目标 ground truth 的攻击者签名（收款人 `US133000000121212121212`、`new_password`、外传 URL 等）；
4. 对照组：direct 基线 vs monitor 基线（同一任务、无注入、两次独立采样）——给出**无注入时的天然分歧率（噪声底）**，这是区分"注入导致的分歧"与"温度 0.6 随机分歧"的统计依据。

**验收门槛**：

| 指标 | 门槛 |
| --- | --- |
| 成功攻击（37+46 条）分歧点命中攻击者签名动作 | ≥ 80% |
| 失败攻击中检出注入分歧的召回率 | 报告数值（无门槛） |
| 干净对照对分歧率（噪声底） | 显著低于攻击对 |
| 载荷未进上下文的运行（~35%）归类为"归因不适用" | 100% |

**产出**：`docs/bankfull_attribution_report.md` + 可复用脚本。

**风险与分支**：若噪声底高到与攻击对无法区分，说明序列级归因不可行，阶段 2 改用参数级归因（只比对分歧调用的参数差异）——负结果本身有报告价值。

## 阶段 2：路径 B 彩排原型（2–3 天）

**目标**：真实工具面上验证"绊网 + 净化重跑"的行为证据检出质量。

**搭法**（复用现有件为主）：

1. 任务面：`seed_workspace`（guard/gateway/runner.py）造工作区，文件内埋 ChatInject 载荷；工具 = `read_file`（exec cat）+ `exec`（shell），执行器均已存在；
2. 绊网层：新增 `guard/sandbox/tripwire.py` 包在 ExecExecutor 外，逐命令扫描并写审计事件 `TRIPWIRE_HIT`，四类信号：
   - 出口尝试：curl/wget 等（`network=none` 下失败——失败本身即高置信信号）；
   - 敏感路径探测：/etc、~/.ssh、/proc/1、宿主路径；
   - 提权尝试：sudo/mount/unshare/setuid;
   - 敏感数据搬运：workspace 内容向 /tmp 或管道汇聚的异常模式；
3. 净化重跑：同一任务两遍——原始工作区 vs 载荷替换为等长良性文本的工作区，对比轨迹分歧（归因逻辑复用阶段 1 结论）；
4. 实验矩阵：~30 个任务 × {良性/注入} × {原始/净化}，约 100–120 次运行；本地 Docker + 少量 API 费用（<¥30）。

**验收门槛**：

| 指标 | 门槛 |
| --- | --- |
| 攻击任务绊网命中率 | ≥ 80% |
| 良性任务绊网误报率 | ≤ 5% |
| 净化对照分歧定位恶意动作 | 复用阶段 1 门槛 |
| 彩排一轮墙钟延迟 | 记录数值（产品化延迟预算依据） |

**产出**：`docs/rehearsal_report.md` + 原型代码（tripwire + 场景 fixtures）。

**风险与分支**：自由文本命令的绊网规则误报多（良性任务也可能 cat /etc/passwd）——误报率是硬门槛，超标则收紧规则或改判据（如要求信号组合而非单信号触发）。

## 阶段 3：产品化为网关第三层（约 1 周，前两阶段达标后启动）

**设计骨架**（启动时出详细设计文档）：

1. 触发条件：不彩排所有任务；策略引擎动作分级中高危类（转账、外发、删除）触发，读操作直接放行（延迟预算决定）；
2. 位置：`GatewaySession.decide()` 的 ALLOW 之后、真实执行之前插入 `RehearsalService`：起沙箱副本 → 绊网收集 → 净化对照 → 裁决（规则 + LLM 混合）→ 裁决作为新事实类型回填策略引擎（与现有语义 facts 回填同构）；
3. 降级路径：彩排基础设施故障回退到判定层单独工作（沙箱硬边界原则不变）；
4. 可观测：彩排全过程进审计库，报告口径与 bankfull 一致。

**验收**：e2e 测试进现有套件；延迟达标；kill-switch 配置项。

## 阶段间依赖

```
阶段 1 ──(归因精度 ≥80% 且噪声底可分)──► 阶段 2 ──(绊网 80%/5% 达标)──► 阶段 3
   │                                        │
   └─ 失败 → 改参数级归因再进阶段 2          └─ 失败 → 收紧绊网规则重测
```

## 已有相关结论（衔接）

- bankfull：判定层 0/432、归因干净（monitor 消融）、基线零误拦——阶段 1/2 的数据与工具基础；
- 沙箱静态边界已有测试覆盖（tests/test_sandbox.py、tests/test_e2e_protocol.py），彩排原型直接建在其上；
- 沙箱威胁模型层（真实注入 → 兜底效果）此前未测——本计划阶段 2 顺带补上这块证据。
