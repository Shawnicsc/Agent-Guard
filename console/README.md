# TraceShield 独立安全控制台

控制台全部位于 `console/`。不改动 `guard/`、默认策略、审计表结构或原有网关 API；无需 LLM、Docker，也不会启动 Agent 或重跑任何实验。

## 启动

已有前端依赖时，构建一次：

```bash
cd console
npm run build
```

缺少依赖时先在 `console/` 执行 `npm install`。前端沿用现有 React、Vite、React Flow，没有新增 npm 依赖；Python 服务复用项目已有依赖。

从项目根目录启动独立服务：

```bash
uv run python console/server.py
```

浏览器打开 **http://127.0.0.1:8001**。服务同时提供构建后的页面和只读数据 API，原网关无需启动。

指定已有审计库或策略文件：

```bash
uv run python console/server.py --db docs/cve_reproduction.db --policy policies/cve_repro.yaml
```

默认读取项目根目录的 `agent-guard.db` 和 `policies/default.yaml`。也支持 `AGENT_GUARD_DB_PATH`、`AGENT_GUARD_POLICY_FILE`；`--db` / `--policy` 优先。审计库不存在时不创建数据库，页面显示缺失状态，历史对抗报告仍然可读。

## 开发方式

一个终端从根目录运行 `uv run python console/server.py`，另一个终端在 `console/` 运行 `npm run dev`，打开 Vite 打印的本地地址。Vite 将 `/api` 原样代理到 `127.0.0.1:8001`，与旧网关端口 8000 分开。

独立服务端口可由 `--port` 修改；开发时同步修改 `vite.config.ts` 的代理目标。构建后由独立服务同源提供页面，无需 Vite 或 CORS。

## 数据边界

- 服务使用 SQLite `mode=ro` 和 `query_only` 读取既有数据库，不实例化会创建/迁移表的 `AuditStore`。复用的 `guard.audit.trace` / `redact` 仅用于只读重建与展示。
- 接口不提供策略修改、调用执行或批准操作。原有系统继续生成审计记录后，可手动刷新，也可勾选每 15 秒更新。
- 内容经过现有脱敏器及控制台补充脱敏；默认不返回模型完整请求/响应。工具结果以原审计保留内容为限。
- “需要确认决策”统计历史裁决次数，不等于当前待批准数量；批准记录分别展示状态与有效期。全库计数与当前会话计数明确区分。
- 当前磁盘策略不代表历史会话生效版本；历史裁决单独展示保存的策略版本。
- 来源原文、文本区间、执行计划等未被原审计保存时显示“未记录”，不合成 token 级定位或未知检测结果。
- 图中虚线为推断关联，实线为观测关联。已执行目标含合法只读访问，不能直接当作受害资源。
- 抗绕过矩阵只表示配置语料是否有历史报告记录；不会把语料存在视作已经通过。银行实验同时展示攻击成功率与合法任务完成率。
- CVE 数据为关联攻击模式的工具调用层验证，不能当成原产品真实漏洞复现。
- “演示场景”是前端内存中的合成数据，始终有显著标识，不写入数据库，也不填充真实实验指标。后端断开时可以手动切换演示；不会静默冒充在线结果。

## 模块文件

- `server.py`：独立只读 API、报告汇总和构建产物托管。
- `src/App.tsx`：导航、连接状态、数据模式和刷新。
- `src/pages.tsx`：总览与五项能力页面。
- `src/TraceGraph.tsx`、`SequenceDiagram.tsx`：交互式链路图、节点证据与调用时序图。
- `src/components.tsx`、`types.ts`、`lib.ts`：展示组件、数据契约和格式化。
- `src/demo.ts`：明确标识的离线演示场景。

验证命令：仓库根目录执行 `.venv/bin/pytest console/test_presentation.py -q`，在 `console/` 执行 `npm run build`，生成供独立服务托管的静态文件。


## 历史报告：运行历史

打开 `http://127.0.0.1:8001/#presentation`，默认查询当前审计库的真实运行，支持日报、月报、北京时间/UTC、日期范围、来源、应用、数据集、批次和关键词筛选。点击日期分类查看汇总及会话列表，进入链路查看具体证据；导出筛选报告包含全部匹配记录。

时间按会话开始时间归档，统计为所选会话的累计审计记录。生产运行、评测和真实 Demo 均可查询，旧会话归属缺失时明确显示“未记录”；前端合成演示数据不计入。刷新后会读取新增记录。写入端与控制台必须连接同一个审计库。

接入示例、批次登记和接口说明见 [运行历史说明](../docs/runtime-history.md)。

## 评测存档

打开“历史报告 → 评测存档”，或 `http://127.0.0.1:8001/?view=catalog#presentation`。存档目录分别列出银行评测、隔离彩排和 CVE 场景报告。该入口独立读取仓库存档，无需审计数据库，不运行模型或攻击；切换审计库或任务不会自动换成另一份实验报告。

- 效果与代价：从银行分片重算三种模式的攻击成功率、合法任务完成率、错误/未知、可见载荷和 BLOCK 判定；两图相同刻度，可下载 SVG。Wilson 区间为逐运行二项描述性区间。
- 覆盖矩阵：按模式、载荷筛选任务 × 攻击目标；点击单元格展开各次运行、原始参数和独立裁决数组，缺失结果保留未知。
- 案例回放：真实彩排调用记录可播放、暂停、单步、拖动进度和导出；不会执行工具。
- 彩排对照：注入运行与独立良性 B1 并列，单独展示净化影子重跑的信号摘要、不可用事件和延迟；不补造未存档的逐步影子轨迹。
- CVE 场景报告：展示每个场景的通过状态、调用数、BLOCK/CONFIRM 和实际执行数，并提供攻击轨迹与逐调用证据；不混入银行评测指标。
- 目录显示各类记录数和存档文件更新时间；更新时间不等同于实验执行时间。实验日期从存档读取，缺失时显示未记录。
- “刷新”重新读取当前存档。银行来源为 `docs/bankfull_*_shard*.json`，彩排来源为 `docs/rehearsal_stage3_eval.json`，CVE 来源为 `docs/cve_reproduction.json`；其他实验尚需接入对应数据源，页面不会自动发现任意新实验。
- 证据清单附当前文件 SHA-256，导出全部 JSON 包含银行、彩排与 CVE 数据；支持展示模式（Esc 退出）与浏览器打印/PDF。

修改后重新 `npm.cmd run build` 并重启 Python 控制台服务。Windows 已配置本地虚拟环境时也可使用 `.venv\Scripts\python.exe console/server.py`，避免每次启动触发环境同步。


## CVE 攻击轨迹图

在“历史报告 → 评测存档 → CVE 场景报告”或“对抗鲁棒性 → CVE 攻击轨迹可视化”查看。读取现有 `docs/cve_reproduction.json`，不需要审计数据库。

- 支持切换 5 个历史 CVE 关联场景，缩放、平移、点击节点和上/下一个调用。
- 每行以一条原始调用为单位，分为候选工具、安全裁决、实际执行三列；实线仅关联同一调用的字段，不推断跨调用因果。
- 场景设计中的攻击步骤单独列出，与实际调用记录分开。未提供的时间戳、来源影响关系和完整 DAG 不补造。
- 证据详情展示参数、原因、规则、executed/ok，支持导出当前场景 JSON。拒绝构造、BLOCK、CONFIRM 与执行失败分别保留。
- 这些是专用策略下的工具调用层模式验证，不等同于真实漏洞产品复现，也不经过 LLM 或 Docker。

## 界面配色

桌面端侧栏底部的“配色”按钮提供蓝紫、青绿、暖砂三套风格，手机端按钮位于顶部导航右侧。选择保存在当前浏览器，下次打开会恢复；禁用浏览器存储时仍可在当前页面切换。页面、图表和轨迹节点同步换色，放行、确认、阻断仍分别使用绿、琥珀、红色。
